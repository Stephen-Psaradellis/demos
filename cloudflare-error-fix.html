Cloudflare error 520 to 526 on your site

Instead of your website, visitors get a plain page with a big number (521, 522, 524...), a short line such as "Web server is down", and a row of three pictures: Browser, Cloudflare, Host. Cloudflare sits in front of your site, so this page means Cloudflare is working but could not get a proper answer from the server your site really lives on. The number tells you which kind of failure it was. Below is a rebuilt example (not a real client), how to read the page, and the fix for each number.

What a visitor sees

What the checks found


  





First: read the error page


    
  
  1. Look at the three pictures. Under Browser, Cloudflare and Host each says "Working" or "Error". For every 52x number, Host is the one marked Error: the problem is at your web host or in your settings, not at Cloudflare. If Cloudflare itself is marked Error, check cloudflarestatus.com and wait.
    2. 
  
  2. Write down the number and the Ray ID (the code at the bottom of the page). The host's support and Cloudflare's both ask for it.
    3. 
  
  3. Is it every page or one action? A whole-site 521 or 522 is a server or firewall problem. A 524 that only appears on an import, a backup or a big report is one slow job.
    4. 
  
  4. Did something change today? A host move, a new security plugin, a renewed certificate or a changed SSL setting in Cloudflare explains most of these within a minute.
    5. 




What each number means and the fix





  
ErrorWhat happenedThe fix

  
521 Web server is downYour server refused Cloudflare's connection. Either the web server is stopped, or a firewall is turning Cloudflare awayAsk the host whether the server and the web service (Apache, Nginx, LiteSpeed) are running. If they are, something is blocking Cloudflare: a host firewall, a security plugin's IP blocking or rate limiting. Allow Cloudflare's addresses, listed at cloudflare.com/ips, in the host firewall and the plugin

  
522 Connection timed outCloudflare knocked and nobody answered in timeThe server is overloaded, a firewall is quietly dropping Cloudflare, or the address in Cloudflare is wrong. In Cloudflare open DNS > Records and compare the IP on your site's A record (and www) with the server IP in your hosting account. After a host move this is the usual cause. If the IP is right, ask the host about load and blocked Cloudflare addresses

  
523 Origin is unreachableCloudflare could not find a route to the server at allAlmost always a wrong or old IP address in DNS > Records, or a server that was switched off or given a new address. Put in the current IP from the hosting account

  
524 A timeout occurredThe server accepted the connection but took too long to send the page (Cloudflare waits 100 seconds on most plans)Find the slow thing, do not just wait longer: a big import, a backup or a report running during the visit, a plugin calling a service that is not answering, or a slow database query. Move long jobs to the command line or a scheduled task, and see slow site and 502 / 504

  
525 SSL handshake failedCloudflare is set to talk to your server securely (SSL mode Full or Full strict), but the server could not set up a secure connectionInstall or renew the certificate on the server (most hosts give a free one in the control panel), or install a free Cloudflare Origin Certificate from SSL/TLS > Origin Server. Check that port 443 is open on the server

  
526 Invalid SSL certificateSSL mode is Full (strict) and the server's certificate is expired, self-signed or made for a different nameRenew the certificate on the server, or replace it with a Cloudflare Origin Certificate, which Full (strict) accepts. Make sure it covers both yourdomain.com and www.yourdomain.com

  
520 Web server returned an unknown errorThe server sent back something empty or broken instead of a pageUsually the site's own code crashed mid-page (look in the host's error log at the time of the Ray ID; see critical error and white screen), a firewall cut the connection, or the reply was too big, often from too many cookies. Try a private window: if the page loads there, the cookies are the cause







A quick test: is the server fine without Cloudflare?


In Cloudflare, Overview has a Pause Cloudflare on Site link near the bottom. Pausing sends visitors straight to your server for a few minutes. If the site loads paused, the server is fine and the problem is between the two: a firewall blocking Cloudflare (521, 522), the SSL mode (525, 526) or the DNS record (523). If it still fails paused, the server itself is down or crashing, and that is a question for the host. Turn Cloudflare back on afterwards; pausing also turns off its protection.



What not to do


    
  
  • Do not switch SSL mode to Flexible to make a 525 or 526 go away. The page between Cloudflare and your server then travels unencrypted, and on WordPress it often causes too many redirects. Fix the certificate instead.
    • 
  
  • Do not keep purging the Cloudflare cache. These errors come from the server, and a purge sends more traffic to a server that is already struggling.
    • 
  
  • Do not move the domain away from Cloudflare in a panic. Changing name servers takes hours to settle and the server problem is still there afterwards.
    • 
  
  • Do not post your server's IP address in public forums while asking for help. Cloudflare hides it for a reason.
    •
