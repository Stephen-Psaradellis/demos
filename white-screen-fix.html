Your WordPress site shows a blank white page

A completely white page, with no message at all, almost always means PHP stopped with an error and the server is set not to show errors to visitors (which is the right setting). WordPress normally catches this and shows "There has been a critical error on this website"; you get plain white when the error happens before WordPress can step in, when that safety net is switched off, or when a cache stored the blank page. Your posts, pages and orders are still in the database. Below is a rebuilt example (not a real client), then the safe order of steps.

What the checks found


  





First: where is it white, and since when?


    
  
  • Check in a private window and on your phone's mobile data. If only your own browser shows white, it is a stored copy: clear that site's cache and purge any caching plugin or CDN.
    • 
  
  • Whole site, only /wp-admin, or one page? Everything white points at a plugin, the theme or PHP itself. Only the dashboard usually means one plugin. A single page usually means a page-builder block or a shortcode on that page.
    • 
  
  • Look in the site admin's inbox for "Your Site is Experiencing a Technical Issue". WordPress sends it when it catches a crash, names the plugin or theme, and includes a recovery-mode login link that lets you in with that plugin paused.
    • 
  
  • Note what changed last: a plugin or theme update, a new plugin, an edit to functions.php, or the host moving the site to a newer PHP version. The cause is almost always the last change.
    • 




The safe order of steps


    
  
  1. Back up the files and the database (host's backup tool, or the file manager plus phpMyAdmin export) before changing anything.
    2. 
  
  2. Read the error instead of guessing. Your host's control panel usually has a PHP "Errors" or "Logs" page. If it shows nothing, open wp-config.php and, above the line that says "That's all, stop editing", add define('WP_DEBUG', true);, define('WP_DEBUG_LOG', true); and define('WP_DEBUG_DISPLAY', false);. Load the white page once, then open wp-content/debug.log. The last "PHP Fatal error" line names the file, and the folder in its path names the plugin or theme.
    3. 
  
  3. If it names a plugin, rename that plugin's folder in wp-content/plugins (add -off). WordPress switches it off and keeps its settings. If you cannot tell which one, rename the whole plugins folder, log in, rename it back, then switch plugins on one at a time until the white page returns.
    4. 
  
  4. If it names the theme (often its functions.php after an edit), undo the edit from your backup, or rename the active theme's folder in wp-content/themes so WordPress falls back to a default theme such as Twenty Twenty-Five. That only works if a default theme is still installed.
    5. 
  
  5. If it says "Allowed memory size ... exhausted", the site ran out of PHP memory. Add define('WP_MEMORY_LIMIT', '256M'); to wp-config.php, and if that does not hold, ask the host to raise the PHP memory limit. Then find what is using it, usually one heavy plugin.
    6. 
  
  6. If the white page started when the host changed PHP version, an old plugin or theme is not written for the new version. Update it, or replace it; switching PHP back in the host's PHP selector is a stopgap for a day, not a fix.
    7. 
  
  7. Switch debugging off again: set WP_DEBUG back to false and delete wp-content/debug.log. That file sits at a public address and can show your folder layout to anyone who asks for it.
    8. 
  
  8. Test the home page, an inner page, the contact or order form and the dashboard login in a private window, then purge every cache so no visitor is served the stored blank page.
    9.

What not to do


    
  
  • Do not leave WP_DEBUG_DISPLAY on for visitors. Error text on the page can show file paths and plugin versions to people looking for a way in.
    • 
  
  • Do not delete a plugin to fix a white screen. Renaming its folder switches it off and keeps its settings and data; deleting can take those with it.
    • 
  
  • Do not restore an old full backup just to clear a white page. Orders, bookings and form entries since that backup would be lost, and the fix is usually one folder rename.
    • 
  
  • Do not paste code into functions.php from the dashboard's theme editor on a live site. One missing bracket is enough to make the whole site white, and the editor cannot be reached to undo it.
    • 



If you can reach the host's file manager and the error log, the steps above are usually enough. If the site earns you money every hour it is blank, that is what the box below is for. Related: "There has been a critical error on this website" is the same kind of crash with WordPress's message on it.
