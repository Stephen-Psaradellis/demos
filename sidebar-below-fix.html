More fixes

WordPress sidebar showing below the content

On a computer the sidebar should sit beside the post, and suddenly it is at the very bottom of the page, under the comments or the footer of the article. Nothing in the theme was changed. In most cases one piece of content broke the layout: a stray </div> tag pasted in with a menu, a table or an ad, or something wider than the column such as a big table, image or video. The first question finds it fast: does it happen on every page, or only some? Below is a rebuilt example (not a real client), how to find the cause, and the fix for each.

The post on a desktop

What the checks found


  





First: is it one page or every page?


    
  
  1. Check on a computer, not a phone. On a phone almost every theme puts the sidebar under the content on purpose, because there is no room beside it. That is not a fault. The problem is when it happens on a wide screen.
    2. 
  
  2. Open three or four pages: the home page, one post, one normal page, and the blog or category page.
    3. 
  
  3. Only some pages are broken? Then the cause is inside the content of those pages (the first two rows of the table below). On the blog or home page, the broken one is usually the newest post, because its excerpt is shown there.
    4. 
  
  4. Every page is broken? Then the cause is in something every page shares: the theme, a plugin, custom CSS, or code added to the header or footer (the last rows of the table).
    5. 




The causes and their fixes





  
CauseHow to spot itWhat to do

  
A stray or missing </div> in a postOnly that post (and the blog page while it is listed) is broken. Paste the page address into the free W3C checker at validator.w3.org/nu: it reports "Stray end tag div" or "Unclosed element div" with the lineOpen the post, switch to the code view (block editor: the three dots, then Code editor; classic editor: the Text tab) and remove the extra </div> or add the missing one. It usually came in with something pasted from another site, a menu or price table, or an old page builder

  
Something wider than the columnA wide table, an image with a fixed width, a video or map embed with width="800", or a very long link with no spaces. The page often also scrolls sideways a littleSet the embed's width to 100%; resize the image in the editor instead of typing a width; turn on the table block's "Fixed width table cells" or split a huge table. A one-line rule in Appearance > Customize > Additional CSS covers most cases: .entry-content img, .entry-content iframe { max-width:100%; height:auto; }

  
Code added to the header or footerEvery page broke at the same time someone added a tracking, chat or ad snippet ("Insert Headers and Footers", WPCode, the theme's "header scripts" box)Remove the newest snippet and reload. Snippets should be only <script> lines; an extra <div> in one breaks every page

  
Custom CSS changed widthsEvery page broke after an edit to Additional CSS or a child theme, often a width or padding on the content or sidebarCopy the Additional CSS somewhere safe, delete the newest rules and reload. Widths that add up to more than 100% once padding is added are the usual culprit

  
A speed plugin combining CSSEvery page broke right after turning on "Combine CSS", "Optimize CSS delivery" or "Remove unused CSS" (WP Rocket, Autoptimize, LiteSpeed Cache, SiteGround Optimizer)Turn that one setting off and clear the cache; if the layout comes back, exclude the theme's main stylesheet from it. More in the changes-not-showing guide

  
A theme or plugin updateEvery page broke right after updates, with no edit by youCheck the theme's changelog or support forum for a layout bug; roll that one update back on a staging copy, or ask the developer. Do not edit the theme's own files: an update would wipe the fix







Finding the wide thing in a long post


If the W3C checker reports no stray tags, something is too wide. In Chrome, open the broken post, right-click, choose Inspect, then the Console tab, paste this line and press Enter. It lists every element wider than the post's column, and hovering one in the list highlights it on the page:


var c=document.querySelector('.entry-content, article, main');[...c.querySelectorAll('*')].filter(e=>e.getBoundingClientRect().width>c.clientWidth+1).forEach(e=>console.log(e))



The sidebar is missing, not below?


    
  
  • The page may use a full-width template. In the editor, look under Page (or Post) > Template, or the theme's own "Layout" or "Sidebar" box under the content, and pick the layout with a sidebar.
    • 
  
  • Many themes set the layout for blog, category and single post pages separately under Appearance > Customize, often in a "Layout" or "Sidebar" section.
    • 
  
  • A block theme (Twenty Twenty-Three and later) has no classic sidebar at all; the column is added in Appearance > Editor > Templates with a Columns block.
    • 




What not to do


    
  
  • Do not edit the theme's own files to force the layout. The next update replaces them. Use Additional CSS or a child theme.
    • 
  
  • Do not deactivate every plugin on a live shop to test. Use a staging copy, or the Health Check plugin's troubleshooting mode, which only changes things for you.
    • 
  
  • Do not hide the sidebar on desktop to "fix" it. The broken tag is still there and usually breaks the footer next.
    • 



For most sites this is one stray tag in one post, a few minutes' work once you know which post. If you would rather hand it over, or it happens on every page, that is what the box below is for. Related: an older site that shrinks on phones, a plugin conflict, and changes not showing.
