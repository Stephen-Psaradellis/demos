WordPress site slow to load

Your WordPress site takes four, six, ten seconds to show anything, on a phone it is worse, and visitors leave before the page appears. "Slow" has two very different causes, and the fix for one does nothing for the other: either the server is slow to build the page, or the page it sends is too heavy. Below is a rebuilt example (not a real client), the two-minute test that tells the two apart, and the fixes for each, cheapest first.

Speed test of the home page, phone

What the checks found


  





First: slow server, or heavy page? (two minutes)


Put your home page address into Google's free PageSpeed Insights (pagespeed.web.dev) and look at two numbers in the report, on the Mobile tab.


    
  
  • Server response time (shown as "Reduce initial server response time" or "Time to First Byte", TTFB). This is how long the server takes before it sends the first byte. Under about 0.8 seconds is fine. Two or three seconds means the server is building every page from scratch, slowly, and nothing you do to the photos will fix that.
    • 
  
  • Total page size ("Avoid enormous network payloads") and the number of requests. A small business home page should be well under 3 MB. 6, 8, 12 MB means the page itself is too heavy: usually photos, then scripts.
    • 



Many slow sites have both. Fix the server side first: it affects every page, and it is often one setting.



If the server is slow


    
  
  1. Turn on page caching. Without it, WordPress runs PHP and dozens of database queries for every visitor. With it, most visitors get a ready-made copy. Many hosts have caching built in (look in the host's control panel, often called "cache", "LiteSpeed Cache" or "performance"); otherwise one caching plugin such as WP Super Cache, W3 Total Cache or WP Rocket. Use one, not two: two caching plugins fight each other.
    2. 
  
  2. Update PHP. In the host's control panel, check the PHP version. Sites still on PHP 7.x are slower and no longer get security fixes; WordPress recommends PHP 8.3 or newer. Take a backup and update plugins first, then switch, and check the site straight after; if a page breaks, switch back and see the critical error guide.
    3. 
  
  3. Find the heavy plugin. A plugin that runs on every page (some sliders, page builders, "related posts", statistics, security scanners that scan live) can add seconds. The free Query Monitor plugin shows which plugin is slow on a page; or deactivate plugins one at a time on a staging copy and re-test. Delete plugins you no longer use rather than leaving them active.
    4. 
  
  4. Clean the database. Years of post revisions, spam comments, expired "transients" and leftover settings from deleted plugins slow down every query. A plugin such as WP-Optimize clears them; take a backup first.
    5. 
  
  5. Then look at the host. If TTFB is still over two seconds with caching on and PHP current, the hosting plan itself is the limit (a crowded cheap shared server). Moving to a better plan or host is the fix; the site does not need rebuilding to move.
    6. 




If the page is heavy


    
  
  1. Photos first. Camera and stock photos are 2-8 MB each; a page needs them at 100-300 KB. Resize to the size they are shown and save as WebP. The big photos guide has the steps. Turn on lazy loading for images further down the page (WordPress does this by default since version 5.5; a builder may switch it off).
    2. 
  
  2. Outside scripts. Chat widgets, booking embeds, review carousels, extra trackers, social feeds and video players each pull in their own scripts, often hundreds of KB. The PageSpeed report lists them under "Reduce the impact of third-party code". Keep the ones that bring customers in; remove the rest. A YouTube video can show a thumbnail and load the player only when tapped.
    3. 
  
  3. Fonts. Five font families in four weights each is a lot of downloads before text shows. Two families, two or three weights, is plenty.
    4. 
  
  4. Sliders and animations on the home page. A five-photo slider at the top loads five big photos before the visitor sees the first. One strong photo is faster and usually converts better.
    5. 
  
  5. Then minify and combine. The caching plugin's options to minify CSS and JavaScript help a little. Do this last and test the site afterwards: it is the step most likely to break a menu or form.
    6.

What not to do


    
  
  • Do not install three "speed" plugins at once. Two caches or two minifiers conflict and can break the site or make it slower.
    • 
  
  • Do not chase a PageSpeed score of 100. A home page that shows its main content in under about 2.5 seconds on a phone is the goal; the last points rarely change how many people call.
    • 
  
  • Do not rebuild the whole site because it is slow. Caching, current PHP, smaller photos and fewer outside scripts fix most slow sites in an afternoon.
    •
