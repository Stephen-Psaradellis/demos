WordPress says "The link you followed has expired" when you upload something

You pick a theme or plugin zip, a video or a big PDF, press Install or Upload, and instead of a progress bar you get a white page: "The link you followed has expired. Please try again." Nothing expired. The file is bigger than your host lets one upload be, so the server throws the upload away before WordPress sees it, and WordPress, finding the form arrived empty, falls back to its generic "expired link" message. Raise the host's limit or put the file on the server another way. Below is a rebuilt example (not a real client), then the safe order of steps.

What the checks found


  





First: is it the size, or a page left open too long?


Different things produce the same message, and one look tells them apart.


    
  
  • It happens every time you upload one particular file (a theme or plugin zip, a video, a large PDF or image) and smaller files upload fine: it is the size limit. Go to Media, Add New and read the line under the upload box, "Maximum upload file size: 2 MB" (or 8, 32, 64). If your file is bigger than that number, that is the whole problem.
    • 
  
  • It happened once, on a settings or editor page you had left open for hours, and the form had nothing large in it: the page's one-time security code really did run out (WordPress's codes last about a day). Reload the page, make the change again and save. Nothing needs fixing.
    • 
  
  • A visitor sees it on your contact or order form: a caching plugin or host cache is serving an old copy of that page with an old security code inside it. Exclude that page from the cache (every caching plugin has an "exclude these URLs" box) and purge the cache.
    • 




The safe order of steps


    
  
  1. Back up the files and the database (host's backup tool, or the file manager plus phpMyAdmin export) before changing server settings. Also download a copy of .htaccess and of any php.ini or .user.ini next to wp-config.php.
    2. 
  
  2. Raise the limits in the host's control panel first. Four PHP settings decide it, and the first two must both be larger than your file:

    upload_max_filesize = 64M
post_max_size       = 64M
max_execution_time  = 300
max_input_time      = 300
    
  On cPanel hosts this is "MultiPHP INI Editor" or "Select PHP Version", then Options. Many managed hosts have a "PHP settings" page instead. Pick a number a little above your biggest file rather than the largest the box allows. Then reload Media, Add New: the "Maximum upload file size" line should show the new number.
    3. 
  
  3. If the panel has no such setting, create a file named .user.ini (or php.ini, whichever your host's help pages name) next to wp-config.php containing the four lines above. These files are re-read on a timer, so allow 5 minutes before testing.
    4. 
  
  4. Only on hosts whose help pages say so, the same values can go in .htaccess as php_value upload_max_filesize 64M and so on. On most modern hosts that line is not allowed and the whole site answers "500 Internal Server Error". If that happens, delete exactly the lines you added and the site comes straight back.
    5. 
  
  5. If you cannot raise the limit at all (some cheap plans cap it), skip the upload form. Unzip the theme or plugin on your computer and copy its folder into wp-content/themes/ or wp-content/plugins/ with the host's file manager or SFTP, then activate it from the dashboard. For video, upload it to YouTube or Vimeo and paste the link into the page: a big video served from your own site is slow for every visitor anyway.
    6. 
  
  6. Test the upload that failed, then the home page, the contact or order form and the login in a private window.
    7.

What not to do


    
  
  • Do not install an "increase upload size" plugin from an unknown author. A plugin cannot lift a ceiling the server sets, and abandoned plugins are a common way sites get hacked.
    • 
  
  • Do not set the limits to huge numbers (2G, unlimited time). It lets one request tie up the server, and on shared hosting the host may suspend the account.
    • 
  
  • Do not edit .htaccess or wp-config.php without a copy you can put back. One wrong line takes the whole site down, not just the upload.
    • 
  
  • Do not upload a bought theme's whole download bundle. Marketplace downloads often hold documentation and child themes too; the installable theme zip is usually inside it.
    • 



If you can reach the control panel, the steps above are usually enough. If the site broke while you were trying, or you need the new theme or plugin in today, that is what the box below is for. Related: a "critical error on this website" after the upload finally works means the new theme or plugin itself is the problem, and a blank white page is the same thing with the message hidden.
