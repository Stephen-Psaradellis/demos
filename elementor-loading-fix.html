Elementor is stuck on the loading screen

You click "Edit with Elementor" and get the spinning logo forever, a grey panel on the left with nothing on the right, or the message "The preview could not be loaded". The public site still works; only the editor won't open. Elementor loads the whole editor in your browser through a few background requests to your own site, so when one of them is cut short (not enough memory, another plugin, a speed setting, the host's firewall) the editor just waits. Two checks tell you which one it is. Below is a rebuilt example (not a real client), the two checks, and the fix for each cause.

Edit with Elementor

What the checks found


  





Check 1: Safe Mode


In the dashboard go to Elementor > Tools, set Safe Mode to Enable and save, then open the page in Elementor again. Safe Mode loads the editor with only Elementor and a plain theme, without touching what visitors see.


    
  
  • The editor opens in Safe Mode: another plugin or your theme is the cause. Jump to "A plugin or the theme" below.
    • 
  
  • It still hangs: the cause is the server or a setting: memory, PHP, the firewall or the site address. Check 2 tells you which.
    • 



Turn Safe Mode off again when you are done.



Check 2: the Network tab


On a computer, open the stuck editor, press F12 (or right-click and choose Inspect), open the Network tab and reload. Type admin-ajax in the filter box and look at the Status column of the rows that appear. Then do the same with the Console tab and read the first red line.



What each answer means





  
What you seeCauseFix

  
admin-ajax.php status 500, or "Allowed memory size exhausted" in the error logThe editor ran out of PHP memoryElementor needs at least 256 MB (Elementor > System Info shows your current limit). Add define('WP_MEMORY_LIMIT', '256M'); to wp-config.php above the line that says "That's all, stop editing". If System Info still shows less, the host's own cap is lower: ask them to raise it, it is a setting on their side. More in "Allowed memory size exhausted"

  
Status 403 on admin-ajax.php, or a page from your host or Cloudflare saying the request was blockedA firewall rule (often ModSecurity, Wordfence or Cloudflare's WAF) took the editor's save-and-load request for an attackAsk the host to check the firewall log for your IP at that minute and allow that rule for /wp-admin/admin-ajax.php; in Wordfence, use "Allowlist" on the blocked request under Firewall. Do not switch the whole firewall off

  
Editor opens in Safe Mode, hangs without itA plugin or the theme loads a script that breaks the editorDeactivate plugins in halves (keep Elementor and Elementor Pro on) until the editor opens; the last half you switched off holds the culprit. Speed and optimisation plugins are the usual suspects, then add-on packs for Elementor that are older than your Elementor version. Update or replace the one you find. Step by step: a plugin update broke something

  
Console shows errors in files with names like rocket-loader, autoptimize or wp-rocketA speed setting combines or delays scripts, including the editor's ownTurn off Cloudflare's Rocket Loader (Speed > Optimization), and exclude the editor from JavaScript delay and combine in your speed plugin; most have an option to skip logged-in users or the elementor scripts

  
"The preview could not be loaded", and the Network tab shows the preview page as 404 or redirectedThe address WordPress uses for itself does not match the one you are on (http vs https, www vs not), or the permalink rules are staleUnder Settings > General, make both addresses identical to the one in your browser bar, including https and www. Then open Settings > Permalinks and press Save without changing anything; that rewrites the rules. See also too many redirects

  
Nothing red anywhere, but it only fails in your usual browserA browser extension (ad blockers and script blockers most often) stops the editor's filesOpen the editor in a private window. If it works there, turn your extensions off one by one

  
Editor opens but the page looks unstyled or oldElementor's generated style files are staleElementor > Tools > Regenerate Files & Data, then clear any cache plugin and your host's cache. More in changes not showing on the live site







Check it worked


Open two or three different pages in Elementor, change a word, press Update and reload the public page to see it. Then check Elementor > System Info once more: the memory line and the PHP version (8.1 or newer is the safe range today) should no longer be flagged. If you changed a firewall or speed setting, open the public site on your phone too, to be sure visitors still get the fast version.



What not to do


    
  
  • Do not reinstall Elementor or roll it back to an old version as the first move. Your pages are stored in the database, not in the plugin, so a reinstall rarely changes anything, and an old version brings back fixed security holes.
    • 
  
  • Do not delete plugins to test them; deactivating is enough and keeps their settings.
    • 
  
  • Do not switch the security firewall off for the whole site. Allow the one rule for the one request.
    • 
  
  • Do not test on the live site during business hours if you can avoid it. Many hosts give you a one-click staging copy to try things on first.
    •
