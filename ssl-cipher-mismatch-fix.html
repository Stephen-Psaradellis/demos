Your site says "ERR_SSL_VERSION_OR_CIPHER_MISMATCH"

Chrome shows "This site can't provide a secure connection. The client and server don't support a common SSL protocol version or cipher suite." Edge says the same, Firefox says "SSL_ERROR_NO_CYPHER_OVERLAP". Despite the wording, it is rarely about ciphers. Almost always the server has no certificate it can offer for that exact address, so it gives up before the page starts. Here is how to tell which case you have, and the fix for each.

What the visitor sees

https://www.shop.harborbakery.example/

What the checks found


  





Find out which case you have


    
  
  1. Try the address with and without www, and on a phone on mobile data. If one form works and the other fails, the certificate covers only one name. If everything fails everywhere, the server has no certificate for the domain at all. If only one computer fails, it is that computer (see the last fix).
    2. 
  
  2. Run the free SSL Labs server test (ssllabs.com/ssltest) on the failing address. "No secure protocols supported" or "Certificate name mismatch" names the case. A list of only TLS 1.0 / 1.1 means the server is too old for current browsers.
    3. 
  
  3. Is the site behind Cloudflare? Open Cloudflare > SSL/TLS > Edge Certificates. A certificate marked "Pending Validation", or none at all, means Cloudflare cannot serve the site over HTTPS yet. Also check the name: the free certificate covers example.com and *.example.com, one level only, so www.shop.example.com is not covered.
    4. 
  
  4. Did it start after a move? A new host, a new IP address, a domain added to a hosting account, or a change of nameservers all leave a gap where the new server has no certificate for the name yet.
    5. 
  
  5. If you can use a terminal: openssl s_client -connect example.com:443 -servername example.com. "no peer certificate available" or "handshake failure" confirms the server has nothing to offer for that name.
    6. 




The fixes, by case


    
  
  1. No certificate for the name on the host: in cPanel > SSL/TLS Status, tick the domain and its www form and click Run AutoSSL (or use the host's Let's Encrypt button). This only works once the domain's DNS points at this host, so fix DNS first if it does not.
    2. 
  
  2. Cloudflare certificate pending: check that the nameservers at the registrar are the two Cloudflare gave you, and that no CAA record in DNS blocks Cloudflare's certificate authorities. Most pending certificates issue within 15 minutes of that being right; until then, set the record to "DNS only" (grey cloud) so visitors reach the host's own certificate.
    3. 
  
  3. A name two levels deep under Cloudflare (www.shop.example.com): rename it to one level (shop.example.com), switch that record to "DNS only", or add an Advanced Certificate that names it.
    4. 
  
  4. Server offers only TLS 1.0 / 1.1: current browsers refuse both. On a managed host ask them to enable TLS 1.2 and 1.3; on your own server update OpenSSL and the web server and set ssl_protocols TLSv1.2 TLSv1.3; (nginx) or SSLProtocol -all +TLSv1.2 +TLSv1.3 (Apache).
    5. 
  
  5. Old cipher list: a hand-written cipher list that only allows RC4 or 3DES gets the same error. Replace it with the host's default or Mozilla's "intermediate" setting.
    6. 
  
  6. Only one computer fails: an antivirus "HTTPS scanning" feature, an office proxy, or a very old browser or operating system. Update the browser, turn off HTTPS scanning to test, and check the clock is right.
    7.

What not to do


    
  
  • Do not tell visitors to "click through". This error has no "proceed anyway" link, and a site no one can open loses every order and enquiry until it is fixed.
    • 
  
  • Do not switch Cloudflare to "Flexible" to hide it. That does not create the missing certificate and often adds a redirect loop.
    • 
  
  • Do not buy a paid certificate first. The free one from the host or Cloudflare covers almost every small business site once the name and DNS are right.
    • 
  
  • Write down every DNS record before changing nameservers, so email and other services can be put back exactly.
    •
