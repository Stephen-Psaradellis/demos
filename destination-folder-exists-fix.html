WordPress install error: "Destination folder already exists"

You upload a plugin or theme and WordPress stops with "Destination folder already exists. Plugin installation failed." WordPress refuses to overwrite a folder that is already in wp-content/plugins/ or wp-content/themes/. Either the plugin really is installed, or an earlier install failed halfway and left its folder behind. Here is how to tell which, and the safe fix for each.

What the owner sees

harborbakery.example/wp-admin/update.php?action=upload-plugin

What the checks found


  





Find out which case it is (two minutes)


    
  
  1. Look at Plugins (or Appearance, Themes). If the plugin is in the list, it is installed and you are trying to install it a second time, usually to update it by hand.
    2. 
  
  2. Not in the list? Then the folder is a leftover. A failed upload, a timeout or a lost connection can leave a half-copied folder that WordPress does not show, because it has no working main file.
    3. 
  
  3. Check the server. In the host's File Manager or FTP, open wp-content/plugins/ (or themes/) and find the folder with the plugin's name. Note its date and size: a leftover is often small or missing files.
    4. 




The fixes, by case


    
  
  1. It is installed and you want the new version: on WordPress 5.5 or newer, the upload screen now offers "Replace current with uploaded" when the zip matches an installed plugin or theme. Take a backup first, then click it. If you do not see that button, your WordPress is older than 5.5; update WordPress first, or update the plugin from the Plugins screen instead.
    2. 
  
  2. It is a leftover from a failed install: back up the site, then delete only that one folder in wp-content/plugins/ (or themes/) and upload the zip again. A plugin that never finished installing has no settings to lose.
    3. 
  
  3. A paid plugin with a licence: deactivate it first (not delete) if your licence is tied to the site, then use "Replace current with uploaded". Its settings live in the database and stay.
    4. 
  
  4. It keeps coming back: the upload is failing partway every time. Look in wp-content/upgrade/ for leftover temporary folders and delete them, then check the upload size limit and the disk space on your hosting plan. A zip bigger than the limit fails the same way each try.
    5. 
  
  5. Folder name matches a different plugin: two plugins can use the same folder name. Check the main file's Plugin Name: in the existing folder before you delete anything.
    6.

What not to do


    
  
  • Do not delete the folder of a plugin that is active and working just to re-upload it. Use the replace button, which swaps the files in one step.
    • 
  
  • Do not delete the whole wp-content/plugins/ folder or rename it to "start fresh". That switches off every plugin at once.
    • 
  
  • Do not overwrite a theme you have edited directly. Your changes are lost on replace; move them to a child theme first.
    • 
  
  • Do not skip the backup. Replacing files is quick, and a backup is the only way back if the new version breaks the site.
    •
