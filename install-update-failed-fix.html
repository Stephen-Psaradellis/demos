A WordPress plugin or theme won't install or update

You click Install or Update and WordPress answers with a short line: "Destination folder already exists", "Could not create directory", "Another update is currently in progress", a form asking for FTP details, or "The package could not be installed". Each line points at one cause, and none of them means your site's content is in danger: posts, pages and settings live in the database, not in the plugin's folder. Below is a rebuilt example (not a real client), then what each message means and the fix for it.

What the owner sees in Plugins, Add New, Upload

petalandstem.example/wp-admin/update.php?action=upload-plugin

What the checks found


  





First, two minutes of checks


    
  
  1. Copy the exact message, including any folder path it prints. The table below is sorted by that wording.
    2. 
  
  2. Look at Plugins (or Appearance, Themes). Is the plugin still listed? A plugin that vanished from the list after a failed update, often with "has been deactivated due to an error: Plugin file does not exist", left a half-copied folder behind.
    3. 
  
  3. Check the disk space in the host's control panel. A full hosting account produces "Could not create directory" and "Could not copy file" with nothing else wrong.
    4. 
  
  4. Wait 15 minutes if the message is "Another update is currently in progress" and nobody else is updating. That lock clears itself.
    5. 




The fixes


    
  
  1. "Destination folder already exists." WordPress will not copy a plugin or theme over a folder of the same name. If the plugin is listed and working, you are installing a newer copy by upload: recent WordPress versions show "Replace current with uploaded" after the upload, so use that. If it is not listed, the folder is a leftover from a failed install or update. In the host's file manager, open wp-content/plugins/ (themes: wp-content/themes/), rename the folder named in the message, say booking-pro to booking-pro-old, then install again. Its settings come back on activation because they were in the database all along. Delete the -old folder once everything works.
    2. 
  
  2. "Could not create directory." or "Could not copy file." or "Could not remove the old plugin." WordPress cannot write to its own folders. In order of likelihood: the hosting account is out of disk space or file count (clear old backups, which are often the culprit); folder permissions are wrong (folders are normally 755 and files 644); or the files belong to a different system user than the one the site runs as, common after a move or after files were uploaded by another account. Permissions you can set in the file manager; ownership the host fixes in a minute if you ask for it in those words. The folder wp-content/upgrade must be writable too, since every update unpacks there first.
    3. 
  
  3. A form asking for "Connection Information" or FTP credentials. This is the same ownership problem as fix 2, seen from the other side: WordPress checks whether it can write files as itself, and when it cannot, it asks for FTP details instead. The lasting fix is correct ownership (ask the host). Adding define('FS_METHOD', 'direct'); to wp-config.php only hides the form; if the ownership is still wrong, the next install fails with "Could not create directory" instead.
    4. 
  
  4. "Another update is currently in progress." A core update leaves a lock while it runs, stored in the options table as a row named core_updater.lock, and it expires after 15 minutes. If an update was interrupted (a closed tab, a timeout) and you cannot wait, take a database backup and delete that one row in phpMyAdmin, or run wp option delete core_updater.lock if the host has WP-CLI. Then run the update once, and let it finish.
    5. 
  
  5. "The package could not be installed. No valid plugins were found." (themes: "...The theme is missing the style.css stylesheet.") The zip you uploaded is not the plugin itself. Paid plugins and themes from marketplaces often arrive as a bundle with documentation, licences and the real zip inside. Unzip it on your computer, find the inner zip named after the product, and upload that one. A theme uploaded under Plugins (or the reverse) gives the same message.
    6. 
  
  6. "Download failed." with "cURL error 28" or "Could not resolve host". Your server could not reach the download address in time. Tools, Site Health shows whether it can reach WordPress.org at all. A one-off timeout passes on the next try; a repeating one is the host's firewall or DNS, which only the host can change. A paid plugin with no licence key entered, or an expired one, usually also fails at the download step; the vendor's message varies, and the fix is the key in that plugin's own settings page.
    7. 
  
  7. "Update failed" on a big plugin or theme you upload by hand, with "exceeds the upload_max_filesize directive" or "The link you followed has expired": the zip is larger than the host allows. That has its own guide: "The link you followed has expired".
    8. 
  
  8. Test: the plugin is listed and active, its settings screen opens with your settings in it, the page that uses it (bookings, forms, shop) works from a private window, and Plugins shows no update stuck half-way.
    9.

What not to do


    
  
  • Do not delete a plugin's folder to "start clean" before you know its settings are in the database. Most keep them there, but some keep files (uploads, generated forms, licence files) inside their own folder. Rename first, delete after the test.
    • 
  
  • Do not set folders to 777 to make an error go away. It lets any process on the server write into your site, which is how many sites get spam injected.
    • 
  
  • Do not click Update again and again on a stuck update. Each try can leave another partial copy; find the message's cause first.
    • 
  
  • Do not install a "nulled" copy of a paid plugin because the download failed. Those copies are the commonest way malware gets into small business sites.
    • 



Most of these take minutes once the message is read correctly; ownership needs one message to the host. If you would rather hand it over, that is what the box below is for.
