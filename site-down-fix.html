A website that stopped loading: getting it back up

A family bakery's website had run quietly for six years. Then the card on file with the hosting company expired, three renewal emails went to an old address nobody checked, and the hosting plan was suspended. The domain name was still paid for, so Google Maps, Yelp and the bakery's Instagram kept sending people to it - and every one of them got a browser error instead of the menu, the hours and the custom-cake order form. The owner only found out when a customer mentioned it at the counter. Here is how the cause was found from the outside, what was done, and how long it took.

Check yours in thirty seconds: turn off Wi-Fi on your phone and open your website on mobile data. Your own computer can show you an old saved copy, so a phone on mobile data is the honest test. If it shows an error, a blank page or a "this domain is for sale" page, your customers see the same thing.

What is usually wrong

"The site does not load" has only a handful of causes, and each one leaves a different trace that can be read from outside, without any login. That is how I can tell you which one it probably is before you share anything.

For the bakery the trace was the first row: the name answered (it still pointed at the hosting company), but the server never did, on http or https, at any hour - a suspended plan, not a broken site.

  connect, port 443 timed out after 15 seconds

After the plan was reactivated:
  connect, port 443 answers, page loads in 1.4 s

  pages checked     home, menu, cake order form, contact - all load

How it was fixed

  1. Diagnose from outside first: does the name resolve, does the server answer, is the domain paid up, is the certificate valid. That pointed at the hosting plan, not the site.
  2. The owner reactivated the plan - a payment, so it is always theirs to make - and moved the renewal emails to an address they read.
  3. Check the site came back whole: after a suspension the files and database are usually intact, but the certificate had lapsed in the meantime and the cake order form's email setting had been reset. Both fixed.
  4. Make it not happen again: auto-renew on the plan, the domain and the certificate, and a free uptime check that emails the owner within five minutes if the site stops answering.
  5. Re-check every main page on a phone on mobile data, and that a test cake order arrives in the owner's inbox.

If the site is gone for good - the host deleted it, or you have since moved to a new one - the old address can still forward to the new site, so map listings and old links do not end on an error. That part is a few minutes of setup at the place the domain is registered.
