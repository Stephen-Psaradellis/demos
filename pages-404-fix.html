Your WordPress home page works, but every other page says "Not Found"

When the home page loads and About, Contact, Services and every blog post give a 404, your pages are almost never gone. WordPress turns a pretty address like /contact/ into "show page 14" using a short set of address rules (your permalinks). The home page needs no rule, so it is the only thing left working when those rules go missing. It typically happens right after a move to a new host, a restore, an SSL or security plugin change, or a server update. Below is a rebuilt example (not a real client), then the safe order of steps.

What the checks found


  





First: which "Not Found" do you get?


This one look tells you which half is broken, before you touch anything.


    
  
  • Your own theme's "page not found" page (your logo, menu and colours around it): the request reached WordPress, but WordPress has no rule for that address. Saving the permalinks again (step 2 below) almost always fixes this. If only one kind of page fails (only products, only events), the plugin that adds that kind of page has rules WordPress never stored.
    • 
  
  • A plain page in a serif font that says "Not Found. The requested URL was not found on this server", or a bare "404 Not Found" with "nginx" under it: the web server answered by itself and never asked WordPress. The rules file the server reads (.htaccess) is missing or broken, or the server is set to ignore it. This is the usual one after a host move.
    • 
  
  • Quick test: open yoursite.com/?page_id=2 (or any page's ID, shown in the address bar when you edit it). If that address shows the page while /about/ does not, the page is fine and only the address rules are missing.
    • 




The safe order of steps


    
  
  1. Back up the files and the database (host's backup tool, or the file manager plus phpMyAdmin export) before changing anything. Also download a copy of .htaccess if it exists: it can hold your https redirect, caching and security rules too.
    2. 
  
  2. Save the permalinks again. In the dashboard go to Settings, Permalinks, change nothing, and press Save Changes. WordPress rebuilds its address rules and, if it is allowed to, rewrites the WordPress block of .htaccess. Test an inner page in a private window. This alone fixes most cases.
    3. 
  
  3. If the page says it could not write .htaccess, or the file is still missing (it starts with a dot, so file managers and migration tools often hide or skip it): in the host's file manager, turn on "show hidden files", open or create .htaccess next to wp-config.php, and make sure it contains WordPress's standard block, unchanged:

    # BEGIN WordPress
<IfModule mod_rewrite.c>
RewriteEngine On
RewriteBase /
RewriteRule ^index\.php$ - [L]
RewriteCond %{REQUEST_FILENAME} !-f
RewriteCond %{REQUEST_FILENAME} !-d
RewriteRule . /index.php [L]
</IfModule>
# END WordPress
    
  If WordPress lives in a subfolder (for example /shop/), both the RewriteBase and the last line use that folder: RewriteBase /shop/ and RewriteRule . /shop/index.php [L]. Keep any other rules already in the file, above or below this block.
    4. 
  
  4. If the file is right and you still get the plain server 404, the server is ignoring it. On Apache that means address rewriting (mod_rewrite) is off or the site's settings do not allow .htaccess (AllowOverride). On nginx, which never reads .htaccess, the site's server block needs try_files $uri $uri/ /index.php?$args;. On shared hosting you cannot change either yourself: send the host's support exactly that sentence and they fix it in minutes.
    5. 
  
  5. If only one kind of page fails (products, events, listings), switch the plugin that adds them off and on again, then save the permalinks once more. Also check that no page or category uses the same address as that section (a page called "shop" and a shop base of /shop/ fight over it).
    6. 
  
  6. Test the home page, three inner pages, a blog post, the contact or order form and the dashboard login in a private window, then purge any caching plugin and CDN so no visitor is still served the stored 404.
    7.

What not to do


    
  
  • Do not switch permalinks to "Plain" to make the pages load. It works, but every address Google, your Google Business Profile and other sites link to changes to ?p=123, and all of those links break instead.
    • 
  
  • Do not delete .htaccess and start over without a copy. On many sites it also holds the https redirect, the www rule, caching and blocked bots; losing those causes the next problem.
    • 
  
  • Do not recreate the pages. They are still in the database, and new copies get addresses like /contact-2/ while the originals sit unreachable.
    • 
  
  • Do not paper over it with a redirect plugin sending every 404 to the home page. Visitors and Google stop seeing errors, but they also stop seeing your pages.
    •
