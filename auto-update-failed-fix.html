Your WordPress site emailed you that an automatic update failed

WordPress updates itself, and many plugins, in the background, and it emails the site's admin address when that goes wrong. The subject line tells you how worried to be. Most of these emails mean "nothing broke, but the update did not happen", which is fixable in a few minutes. One of them means the site may be down right now. Below is a rebuilt example (not a real client), what each email means, the five-minute check, and the fix for each cause.

The five-minute check


    
  
  1. Open the site in a private window. If it loads normally, nothing is broken and you can take your time. If it does not, start with the first row below.
    2. 
  
  2. Go to Dashboard > Updates. It lists what is still out of date. Click Update on one failed plugin by hand: the error it shows (if any) is the real reason the background update failed. Plugin or theme won't update explains each of those errors.
    3. 
  
  3. Open Tools > Site Health. The Background updates test says in plain words whether automatic updates can run on this site and, if not, why: files not writable, a version-control folder, or updates turned off in wp-config.php. The scheduled event test tells you whether the background jobs that run the updates are running at all.
    4. 
  
  4. Open Site Health > Info > Filesystem Permissions. Every line should say Writable. Also check the disk space your host shows: a full disk fails every update.
    5. 




What causes it and the fix





  
What you seeWhy it happensThe fix

  
The URGENT email, and the site shows "Briefly unavailable for scheduled maintenance" or an errorThe update stopped half way. WordPress leaves a file called .maintenance in the site's main folder while it updates, and a half-copied set of core files can break every pageIn the host's file manager, delete .maintenance from the main folder (see stuck in maintenance mode). If the site still errors, use Dashboard > Updates > Re-install version, or upload fresh wp-admin and wp-includes folders of the same version. Never replace wp-content: that is your theme, plugins and uploads

  
Site Health says files are not writable, or updating by hand asks for FTP detailsThe web server is not allowed to write to the site's own files, usually after a migration or a manual upload with the wrong ownerAsk the host to set the file owner to the web server user (folders 755, files 644 is the usual target). Do not set anything to 777: that lets anyone on a shared server change your files

  
One plugin fails every time; by hand it says "Download failed", "Unauthorized" or "update package not available"It is a paid plugin or theme whose license expired or is not entered on this site, so its update server refuses to hand over the new versionRenew or re-enter the license in that plugin's settings, or download the new version from the seller's account page and upload it under Plugins > Add New > Upload. A plugin with no updates for a year is a security risk on its own

  
Site Health says background updates are disabled, or mentions a .git or .svn folderA line in wp-config.php such as AUTOMATIC_UPDATER_DISABLED or WP_AUTO_UPDATE_CORE set to false turns them off, often added by a past developer. WordPress also skips automatic updates when it finds a version-control folderIf nobody updates the site by hand, remove the line (keep a copy) so security releases install themselves. If a developer deploys the site from a repository, leave it and have them update in that workflow

  
The scheduled event test fails, or you get the "Please update!" email every timeBackground updates run through WordPress's scheduler (wp-cron), which only runs when someone visits. A site with few visits, a blocked wp-cron.php, or DISABLE_WP_CRON with no replacement never gets to run themIf DISABLE_WP_CRON is in wp-config.php, ask the host to call https://yoursite.com/wp-cron.php every 5 to 15 minutes. Same cause as scheduled posts not publishing

  
Updates fail with "could not copy file", "Another update is currently in progress", or time outThe disk is full, PHP ran out of time or memory during the unpack, or an earlier failed run left a lock behindFree disk space (old backups stored inside the site are the usual culprit). A stuck lock clears itself in about 15 minutes; try again after that. Memory errors: see memory exhausted

  
The email says a plugin update was rolled back, or the site broke right after an updateThe new version does not work with your PHP version, your theme or another pluginStay on the old version for now and turn off that plugin's auto-update in Plugins. Check its changelog and support forum for a fix, and update after it ships. A white screen or "critical error": see critical error







What not to do


    
  
  • Do not ignore a "failed to update" email because the site still works. The plugin is still on the version the update was meant to replace, and security fixes are the usual reason for an update.
    • 
  
  • Do not turn automatic updates off to stop the emails. You stop the warnings, not the problem.
    • 
  
  • Do not set files or folders to 777 to make updates work. It works, and it lets other accounts on the server change your site.
    • 
  
  • Do not replace the wp-content folder when you re-install WordPress. That is where your site actually lives.
    • 



Most of these take minutes once you know the cause; fixing file ownership with a host, recovering a site that went down mid-update, or getting a paid plugin back on its update channel is where most owners would rather have someone do it.
