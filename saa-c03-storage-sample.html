Choosing storage: Amazon S3, EBS and EFS

Domain focus: design high-performing and cost-optimized architectures.

Most storage questions on the exam are not asking what a service is. They describe a workload and ask which storage fits it. Three questions settle nearly all of them: how is the data accessed, how many machines need it at once, and where does it have to survive a failure.

Three different kinds of storage

Amazon S3 is object storage. You store and fetch whole objects over an HTTPS API, each under a key in a bucket. Nothing is mounted and there is no file locking or in-place editing: changing one byte means writing the object again. In return, S3 scales without any capacity planning, the standard storage class keeps data across at least three Availability Zones, and it is designed for 99.999999999% (eleven nines) durability. It suits backups, logs, media, data lakes and static website assets.

Amazon EBS is block storage. A volume behaves like a disk attached to an EC2 instance, so the operating system can put any file system on it. That makes it the default for boot volumes and for databases that need low-latency random reads and writes. The key limit is location: a volume lives in one Availability Zone and attaches only to instances in that same zone. To move it, you take a snapshot (stored regionally, and incremental after the first) and create a new volume from the snapshot in another zone.

Amazon EFS is a shared file system. It speaks NFS, so many Linux instances, containers and Lambda functions can mount the same directory tree at the same time, across Availability Zones. It grows and shrinks on its own and you pay for what is stored. It suits shared content directories, home directories and any application that expects ordinary POSIX files on more than one server.

When and why to choose each

Start with the access pattern. If the application calls an API or simply needs somewhere durable and cheap to keep files it reads whole, choose S3. If one server needs a fast disk, choose EBS. If several servers need the same files through normal file operations, choose EFS.

Then check the failure requirement. A design that must survive the loss of an Availability Zone cannot keep its only copy of the data on an EBS volume, because the volume is lost to the application for as long as its zone is unavailable. S3 and regional EFS already span zones.

Then check cost. For the same amount of data S3 is the cheapest of the three, EBS sits in the middle, and EFS standard storage costs the most per gigabyte. Each has cheaper tiers for data that is rarely touched: S3 storage classes down to S3 Glacier Deep Archive, and EFS Infrequent Access, with lifecycle rules to move data automatically.

Exam cue. "Shared", "concurrent" or "multiple instances across Availability Zones" with Linux points to EFS. "Windows", "SMB" or "Active Directory" points away from EFS to Amazon FSx for Windows File Server. "Lowest cost" with "rarely accessed" points to an S3 archive class. "Temporary", "scratch" or "can be recreated" with very high I/O points to instance store, which is erased when the instance stops or terminates.

One trap is worth knowing. EBS Multi-Attach lets certain Provisioned IOPS volumes attach to several instances, but only inside a single Availability Zone and only with software that coordinates the writes. It is not a general shared file system, and it is rarely the right answer when the question says "across Availability Zones".

Practice questions

Question 1

A company runs a content management application on Linux EC2 instances in an Auto Scaling group that spans three Availability Zones. Editors upload images, and every instance must see each upload immediately as a normal file path. The application code cannot be changed. Which storage solution meets these requirements?

  1. An Amazon EBS Provisioned IOPS volume with Multi-Attach enabled
  2. An Amazon EFS file system mounted on every instance
  3. An Amazon S3 bucket that each instance syncs to local disk every five minutes
  4. Instance store volumes replicated with a scheduled copy job
Answer and explanation

B. EFS gives many Linux instances in different Availability Zones the same POSIX directory at the same time, with no code change.

A is wrong because Multi-Attach works only within one Availability Zone and needs cluster-aware software. C is wrong because a five-minute sync is not immediate and copies drift apart. D is wrong because instance store is local to one instance and is lost when it stops or terminates.

Question 2

An EC2 instance in one Availability Zone runs a reporting database on an Amazon EBS volume. The team wants a copy of the database running on a new instance in a second Availability Zone of the same Region. What should a solutions architect do?

  1. Detach the volume and attach it to the new instance in the second Availability Zone
  2. Enable Multi-Attach on the volume and attach it to both instances
  3. Create a snapshot of the volume, then create a new volume from the snapshot in the second Availability Zone
  4. Change the volume type so that it becomes a regional volume
Answer and explanation

C. An EBS volume belongs to one Availability Zone. Snapshots are stored at the Region level, so a new volume can be created from one in any zone of that Region.

A is wrong because a volume can attach only to instances in its own zone. B is wrong for the same reason: Multi-Attach does not cross zones. D is wrong because no EBS volume type is regional.

Question 3

A financial firm must keep transaction records for seven years to meet a regulation. The records are almost never read; when an auditor asks, receiving them within 12 hours is acceptable. Which storage option has the lowest cost?

  1. S3 Standard-Infrequent Access
  2. S3 Glacier Instant Retrieval
  3. S3 Glacier Deep Archive
  4. Amazon EFS with the Infrequent Access storage class
Answer and explanation

C. S3 Glacier Deep Archive is the lowest-cost S3 storage class and its standard retrieval completes within 12 hours, which the requirement allows.

A and B are wrong because they cost more per gigabyte to provide retrieval speed this workload does not need. D is wrong because EFS is a file system priced well above S3 archive classes and nothing here needs file access.

Question 4

A company will serve a static marketing website to visitors worldwide. The security team requires that the files cannot be fetched directly from storage, only through the content delivery layer. Which combination of actions meets these requirements? (Select TWO.)

  1. Store the files in an Amazon S3 bucket with Block Public Access turned on
  2. Store the files on an Amazon EBS volume attached to a web server
  3. Add a bucket policy that allows public read access to all objects
  4. Create an Amazon CloudFront distribution that uses origin access control to read from the bucket
  5. Store the files in Amazon EFS and mount it from each edge location
Answer and explanation

A and D. A private S3 bucket holds the files, and CloudFront with origin access control is the only identity the bucket policy allows to read them, so visitors must come through CloudFront.

B is wrong because it adds a server to manage and a single-zone disk for content that needs neither. C is wrong because it permits exactly the direct access the security team forbids. E is wrong because EFS cannot be mounted from edge locations.

Question 5

A genomics team runs a batch job on a single EC2 instance. The job writes many gigabytes of intermediate files, needs the highest disk I/O it can get, and deletes the files when it finishes. If the instance fails, the job is simply restarted from the source data in Amazon S3. Which storage should hold the intermediate files at the lowest cost?

  1. An instance store volume on an instance type that provides one
  2. An Amazon EFS file system
  3. A second Amazon S3 bucket
  4. An Amazon EBS Provisioned IOPS volume with daily snapshots
Answer and explanation

A. Instance store is physically attached to the host, gives very high I/O, and is included in the instance price. Its weakness, losing data when the instance stops or fails, does not matter because the files can be recreated.

B is wrong because nothing is shared and network file storage is slower and costs more. C is wrong because object storage is a poor fit for heavy random scratch I/O. D is wrong because it pays for durability and backups the workload does not need.

Question 6

A company is moving a Windows application to EC2 instances in two Availability Zones. The instances need a shared drive reached over SMB, with access controlled through the company's Microsoft Active Directory. Which service should a solutions architect recommend?

  1. Amazon EFS
  2. Amazon FSx for Windows File Server
  3. Amazon S3 with a bucket policy per department
  4. An Amazon EBS volume shared between the instances
Answer and explanation

B. FSx for Windows File Server is a managed Windows file system that supports SMB and integrates with Active Directory, and it can be deployed across two Availability Zones.

A is wrong because EFS uses NFS and is not supported on Windows instances. C is wrong because S3 is not an SMB share. D is wrong because an EBS volume stays in one Availability Zone and is not a shared drive.
